## GPU factory glue (`hip/gpu_executor_factory.{hpp,cpp}`)
`CreateGpuExecutor(const ModelWeights&, const ExecutorConfig&, std::string*)` in `gufo_ricursive_gpuexec`; `RICURSIVE_HAVE_GPU_EXECUTOR` is defined on `gufo_ricursive` and `gufo_ricursive_gpuexec` only when the HIP target exists. One `SharedModel` (reader + `DeviceModel`) per registered `ModelWeights`, cached by weak pointer, so it is uploaded once and freed with the last executor. F16 KV is the `ExecutorConfig` default and is not touched; the context cap is `config.max_context` (0 -> `NormalizeConfig`: min(32768, GGUF)). Never throws: `NormalizeConfig` (refuses unsupported models before any upload), upload and `GpuExecutor` construction sit in one try/catch that sets `*error`.

Mismatches found between the two packages and what the glue does:
1. **Reader missing.** Engine signature passes only `ModelWeights` (`src/executor_factory.hpp:62`, `src/engine.cpp` CreateSession); `DeviceModel::Upload` needs the `GgufReader` (`hip/device_model.hpp:36`) for the mapped regions, and the host embedding table points into its mapping. Glue: `RegisterGpuWeightsReader(weights, reader)`; the one edit to a package file is a call in `Model::Load` (`src/engine.cpp`, under the macro). Without registration the factory returns nullptr with an error.
2. **Lifetime.** Engine: "released with the last executor and the weights object gone"; executor: `keep_alive` is an opaque `shared_ptr<const void>`. Glue: aliasing `shared_ptr<const DeviceModel>` over a holder that also owns the reader; the registry holds weak references only. A re-registration with another reader drops the cached upload (address reuse).
3. **Error model.** Engine: never throws. Executor: `GpuExecutor` constructor throws, `DeviceModel::Upload` returns nullptr + error. Glue converts both.
4. **`DeviceUsable()` is not reachable.** `OpsExecutor::DeviceUsable` (`hip/executor.hpp:63`) is not part of `Executor`; the engine polls an `ext::DeviceProbe` (`src/runner.cpp:105-111`). A sticky HIP error is therefore only seen through the probe. NOT reconciled (would need an interface change); reported.
5. **`kDefaultContextCap` defined twice** in the same namespace, `src/engine.hpp:34` and `hip/executor.hpp:23` (same value). A translation unit including both fails to compile; the glue includes only the second. Not changed.
6. **KV type.** Engine doc: F32 only together with `exact`; executor allows F32 without `exact`. Glue passes both through (the logits tool uses it).
7. **Batch invariance.** Engine passes up to 2048 rows; the GPU executor is bit-batch-invariant only up to 16 rows with quantized weights (`ExecutorInfo::batch_invariant_rows`, W8A8 above). The engine already treats the GPU as non-exact (`incremental_text_is_exact` only on exact backends); chunked and one-shot prefill of the real model are therefore not bitwise equal on the GPU. Unmeasured.
8. **Build graph.** Engine doc: "links its library into `gufo_ricursive`"; the executor library links `gufo_ricursive`. Static libraries, so the cycle is legal; `extension.cmake` links `gufo_ricursive PUBLIC gufo_ricursive_gpuexec`.
9. **Release build lacks the CPU backend unless `BUILD_TESTING` is on** (engine doc: `gufo_ricursive_reference` requires `testing`). Executables are `test`-role targets too, so the logits tool also needs it.

## Logits tool and scorer
`ricursive_gpu_logits MODEL.gguf TOKENS.i32 OUT.f32 [--rows N] [--kv f16|f32] [--exact] [--context-cap N] [--last-only]` (`tools/gpu_logits.cpp`). Defaults: rows 256, kv f16 on the GPU (f32 on the CPU backend), context cap = token count. `--last-only`: non-final passes skip the head, the file holds only the final position ([1][vocab]). Prints load time, tokens/s, and device memory in use from `hipMemGetInfo` before and after the passes (device-wide, there is no per-process peak API). Exits 1 on any NaN/Inf logit. `tools/score_logits.py REF TEST --vocab N [--max-abs X] [--min-top1 F]`. List mode (2026-11-10, for the S3 real-weights run): `ricursive_gpu_logits MODEL --list PAIRS.txt [options]` loads the model once and runs every `TOKENS.i32 OUT.f32` line, `Reset()` between texts, each text chunked as the single mode would; proven bit-identical to single-file runs on tinyB with the CPU backend only (equal and mixed lengths, rows 16). `tools/score_pooled.py` scores two directories of per-text logits pooled, against a floor, with an explicit verdict (PASS/REVIEW/FAIL); driver `/server/staging/ripple-gufo/s3/run-s3.sh`, notes `/server/staging/ripple-gufo/s3/RUNBOOK.md`.
